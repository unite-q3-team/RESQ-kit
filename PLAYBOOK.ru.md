# PLAYBOOK — погружайтесь в любой Q3 VM этим набором. Анализируйте, декомпилируйте, пересобирайте.

> Перевод [PLAYBOOK.md](PLAYBOOK.md); при расхождениях приоритет у английского оригинала.

Постоянные приказы: [`AGENT.ru.md`](AGENT.ru.md). Этот файл описывает, как провести проект от `.qvm` до identity C (и опционального round-trip), не повторяя известных ловушек.

## 0. Форма проекта

1. **Мод** — `vm/*.qvm` внутри pk3 мода (pk3 = zip).
2. **Артефакты** — identity C, struct dump'ы, sigs/names, trap-логи. Живут под `work/<project>/`, а не внутри дерева исходников игры.
3. **Опциональный скелет** — только если пользователь просил порт. Этого набора он не касается.

Минимальная документация проекта (если вы портируете): журнал прогресса и таблица «функция байткода ↔ роль ↔ доказательство (fn + insn или строка)».

## 1. Настройка

```
work/<project>/
  <mod>.qvm
  <mod>.sigs / <mod>.names     # optional
  <mod>/<mod>.c                # identity C
  <mod>/<mod>.struct.c         # structured dump (do not compile)
```

- Положите `.names` рядом с QVM; эмиттер подхватывает их по суффиксу.
- Выравнивание имён: соберите стоковый модуль того же класса (game/cgame/ui), затем `probe_align <ref.qvm> <ref.map> <mod.qvm>`. 30–45% попаданий против неродственного скелета — норма.

## 2. Опознание функций

Приоритет улик:

1. строки формата (`dump.py find/str`)
2. traps (`probe_inventory`) и порядок соседей (lcc сохраняет порядок файла)
3. размеры структур, смещения полей, индексы configstring
4. граф вызовов (`probe_findcall`, `idcallers.py`)
5. выровненные имена

Типичные приметы: `player_die` — строки Kill:/obituary; `RunFrame` — счётчик кадров + периодические вызовы; `ClientCommand` — цепочка `trap_Argv(0)`.

Ловушка: `probe_inventory` пропускает функции без traps и без строк. Дыра в списке реальна; найдите запись через `probe_findfn`.

## 3. Чтение identity C

- Поток управления совпадает с байткодом 1:1. Struct dump читается легче и может **лгать** насчёт вложенности циклов — сверяйтесь с identity C.
- **Правило смещений:** `qvm_mem + N` ↔ истинный адрес VM `N + 4` (слово 0 blob — NULL-дозорный). Сырой дизасм использует истинные адреса.
- Записи в поля обычно двухшаговые: `loc = base + OFFSET; *loc = *loc + k;` — `tools/scripts/twostep.py`.
- Перемещённые указатели на функции в blob — голые `fn_NNNN,` (без каста). Grep по `(int)fn_` их пропускает.
- Trap-логи ставят **номер syscall первым**: `[18, 672, ptr]` — это `SetConfigstring(672, ptr)`, а не configstring 18.

## 4. Факты о QVM

- Классический заголовок id: литералы сразу после data. Некоторые ассемблеры добавляют лишний завершающий int после `bssCount` — игнорируйте его; раскладку определяйте по размеру файла.
- Размер blob при emit = реальный `data+lit+bss` (+ дозорный), **не** `pow2(dataMask)`. Pow2-добивка взрывает `MAX_IMAGE` q3asm.
- Проверьте лимит вашего q3asm (классика 0x400000, некоторые сборки 0x800000). Держите blob компактным.

## 5. Оракул паритета

```
probe_seqdiff <orig.qvm> <rebuilt.qvm>     # qagame-class
probe_cgamediff / probe_uidiff             # cgame / ui
probe_check <rebuilt.qvm>
```

- `QVM_SEQ_MEMDIFF=1` — пословные расхождения после INIT в ячейках перемещённых указателей на функции ожидаемы (индексы нового кода). Классифицируйте, прежде чем «чинить».
- `QVM_RELOC_DEBUG=2` — каждое слово blob, похожее на ENTER.
- Бюджет шагов пересборки равен orig + 50000 на вызов; перерасход часто означает цикл, но цикл из 4 итераций может ложно сработать в наивном детекторе повторов.

## 6. Если вы портируете (опционально)

- Байткод побеждает. Скелет против байткода → правьте скелет.
- Каждая правка ссылается на доказательство (fn + insn или строка). Нет доказательства — нет правки.
- Компилируйте изменённый файл до записи в журнал; удаляйте остаточные `.asm`.
- Таблицы данных генерируйте из байткода (`tools/scripts/tablewalk.py`, `gen*.py`) с адресами в CLI.

## 7. Ловушки окружения

PowerShell 5.1: нет `&&`; `>` пишет UTF-16LE; `Set-Content -Encoding UTF8` ставит BOM, ломающий cpp. Инлайн-Python с кавычками/регэкспами — в отдельный файл. Вызывайте `emit_qvm.ps1` без `2>&1`. `.ps1`-скрипты набора держите чисто ASCII (либо сохраняйте в UTF-8 *с* BOM): 5.1 читает файлы без BOM как ANSI, и один em-dash однажды сломал парсинг `build_qvm.ps1`.
