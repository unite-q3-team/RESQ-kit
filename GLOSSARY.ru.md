# Глоссарий

> Перевод [GLOSSARY.md](GLOSSARY.md); при расхождениях приоритет у английского оригинала.

Этот набор — только **рекомпилятор**: любой Quake 3 `.qvm` → C → q3lcc → играбельный `.qvm` (`seqdiff` 0). Не компилируйте identity `.c` как игровой код. Не «чините» эмиттер во время чтения дампа.

---

## Три VM

Quake 3 **мод** — это три байткод-модуля, а не одна программа.

| модуль | работает на | типичный файл |
|--------|---------|--------------|
| **qagame** | выделенный / listen **сервер** | `vm/qagame.qvm` |
| **cgame** | **клиент** (HUD, предсказание, события) | `vm/cgame.qvm` |
| **ui** | **меню** (браузер серверов, запуск сервера, настройка) | `vm/ui.qvm` |

**pk3** — zip-архив, который движок загружает как каталог игры.

**baseq3a** — близкое к стоку дерево исходников Quake 3. Выравнивание (`probe_align`) по id Tech3 / baseq3 `game.qvm` + `game.map` — подсказка для имён, а не порт.

## Файл QVM и память VM

**QVM** — байткод Quake Virtual Machine (`.qvm`). Заголовок плюс **code**, затем **data+lit**. BSS в файле *не* хранится.

**insn** — индекс инструкции (единица счётчика команд VM). Identity C помечает их `L107760:`. Это не байтовое смещение в файле.

**CONST** — опкод, кладущий на стек 32-битную константу. Это число может быть int, точкой входа функции или **адресом данных VM** (строка, таблица, ячейка BSS). Identity-комментарии вида `qvm_mem + 45487` — этот адрес минус 4 (см. **−4**).

**data** (`dataLength`) — инициализированные глобалы: таблицы указателей, блоки значений cvar по умолчанию, таблицы переходов. Присутствует в `.qvm`.

**lit** (`litLength`) — C-строки только для чтения, сразу после data в файле. `dump.py str` / `find` видят **только data+lit**.

**BSS** — **Block Started by Symbol**. Классическое имя линкера для *неинициализированных* глобалов (Unix `.bss`). В заголовке QVM есть `bssLength`; эти байты — **нули при исполнении и их нет в файле**. Движок выделяет `data+lit+bss` (с округлением вверх до степени двойки) и заполняет хвост нулями.

  Что там живёт: `g_entities[]`, `g_clients[]`, `level`, cgame `cg` / `cg_entities[]`, частицы и другие большие массивы. В identity C ячейка BSS — это `*(int*)(1767984)` или `qvm_mem + N` **без** строки рядом.

**dataMask** — размер сегмента данных VM минус один: следующая степень двойки от `(data+lit+bss)`, минус 1. Обращения заворачиваются этой маской.

**blob / `qvm_mem_words` / `qvm_mem`** — identity-отображение data+lit+bss в рекомпиляторе плюс 4-байтовый NULL-дозорный по адресу VM 0. Размер равен этому диапазону, **а не** `dataMask+1` (pow2-добивка переполняет `MAX_IMAGE` q3asm). Эмитится как `void *qvm_mem_words[N] = { (void*)0x…, … }`. Огромные `.c` файлы — это blob, а не текст функций. Настоящие C-глобалы **сдвинули бы BSS** и сломали trap-указатели.

**−4 / image offset** — `qvm_mem_words[0]` — адрес VM **4** (NULL-дозорный занимает 0..3). Поэтому emit пишет `qvm_mem + (CONST − 4)`. `dump.py str` печатает walk-back / at / **+4**, потому что комментарии часто на 4 байта внутри строки или за 4 байта до неё.

**vec4 / указатель цвета** — `trap_R_SetColor` и `menutext.color` принимают указатель на четыре float. lcc **не** выравнивает их по 16. Identity `qvm_mem + N` — это **CONST−4**: непосредственное значение байткода обычно **N+4** (так `qvm_mem + 10904` — жёлтый по адресу 10908, а не white.a по 10904). `dump.py color N` печатает RGBA по N−4 / N / N+4; при равенстве предпочитает **+4**. `probe_findconst` идёт по **индексу инструкции** (не по байтам `insn.size`). `probe_data` печатает `f=` и метку `vec4(...)`. Не привязывайте N к границе 16 байт.

**Таблица cvar / `dump.py cvar`** — игровые CONST: `vmCvar+8` (float `.value`, часто проверяется как `int != 0`) или `+12` (`.integer`), плюс совпадения identity где угодно в `[vm, vm+271]`, плюс taint опкодов / прослеживание указателя таблицы, когда в identity нет `qvm_mem+N`. Пропускайте Register/Update по **диапазону insn** (обход таблицы + trap), а не по именам оверлея `Register*`. Некоторые моды хранят dword'ы имени таблицы по `find_off+0x100`; `ptrs` ищет и там. `xref NAME` следует только за C-строкой. См. [docs-ru/CVAR_XREF.ru.md](docs-ru/CVAR_XREF.ru.md).

**stride** — размер одного элемента массива в байтах, восстанавливается из адресной арифметики. **base** — CONST-адрес массива (`g_entities` / `g_clients` / `level`). Вместе они — **ключ пространства данных**. `toolchain/qvm/src/types.rs` поставляется как пустой шаблон; заполняйте его только парами base+stride, которые доказали для своего модуля.

## Сгенерированный C («мономодуль»)

**identity emit / identity dump** — вывод `probe_emit`: один `.c` на VM, gotos, `loc_0`, blob. Собран так, чтобы проходить round-trip через q3lcc. **Оракул на вопрос «что делал байткод».** *Заголовки* оверлеев у этих функций часто лгут.

**structured dump / `*.struct.c`** — тот же байткод, `if`/`while` + имена полей оверлея. **Не компилировать.**

**`--no-typed` (по умолчанию)** — generic emit: без структур оверлея, голые `*(int*)`. **`--typed`** включает `types.rs` (ключ мода, восстановленный в этот шаблон). Не передавайте `--typed`, пока шаблон не заполнен.

**typed emit** — identity C плюс макросы `types.rs` (именованные ячейки, struct-view). Всё ещё blob. Хорош настолько, насколько корректен заполненный ключ.

**`loc_0` / `loc_N`** — слова на **программном стеке** VM (кадр функции), не BSS. `loc_0` — blob кадра. Не вставляйте `loc_*` в дерево исходников игры.

**`va(p0…p59)`** — identity всё ещё использует широкие varargs VM (`G_Printf` с десятками аргументов `int`). Настоящие исходники игры используют C `va()`.

**Имя оверлея / `fn[N]`** — человеческий заголовок из `.names` / `struct.c` (`fn[3] G_FindTeams`). **Имена оверлея лгут:** заголовком может оказаться столкнувшееся стоковое имя, тогда как тело принадлежит другой функции. **Побеждают identity `int Name(` + первый `L<insn>`.**

**`.names` / `.sigs`** — имена функций против кадров/арности из байткода (`names/`). Не оверлей данных.

**Ключ / оверлей (данные)** — именованная раскладка BSS/data (`types.rs`). Отличается от `.names`. Не выдумывайте имена полей из hex.

## Инструментарий и проверки

**q3lcc / q3rcc / q3cpp** — lcc, перенацеленный на QVM (C89). Нельзя `int x;` после операторов; нельзя `for (int i`. Вложенный `{ int x; }` допустим.

**q3asm** — собирает `.asm` + `syscalls.asm` → `.qvm`.

**trap / syscall** — вызов из QVM в **движок** (`trap_SendServerCommand`, `trap_Cvar_Set`, …). В байткоде это отрицательный CONST. Seqdiff сравнивает **поток** таких вызовов, а не байты `.qvm`.

**seqdiff** — упорядоченное сравнение trap-логов orig против rebuilt (`probe_seqdiff` / варианты cgame/ui). Планка рекомпилятора. **fc** — побайтовое сравнение файлов в Windows.

**probe_emit** — декомпиляция → собираемый C + syscalls. Живой crate: `toolchain/qvm/`.

**dump.py** — оракул по строкам, xref, insn, слотам, таблицам указателей: `python tools/dump.py --qvm …`. Не начинайте с grep по дампам в 80k строк. **xref** = строка → `qvm_mem + N` в identity. **cvar** / **cvars** = строка таблицы cvar → загрузки `vmCvar+8` / `+12` (пустой **xref** имени ≠ неиспользуется). **ptrs** = dword'ы данных, указывающие на CONST (также `+256`; когда xref пуст). **slot** = обращения к полям `+OFF`. **hdr** = размеры data/lit/bss.

## Чего в этом наборе нет

**Порт** переписывает поведение в дерево исходников (например, baseq3a). В этот zip такое дерево не входит. Не выдумывайте `pers.*` / pad-имена из hex. Называйте поле только тогда, когда это доказано байткодом + строками.

**C89** — язык, который принимает компилятор QVM. PowerShell вдобавок алиасит `cpp` → `Copy-ItemProperty`; компилируйте q3lcc через `cmd.exe`.
